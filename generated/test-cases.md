# Test cases

User story: As a shopper, I want to log in with my username and password so that I can see the product list and buy items.

| ID | Title | Type | Steps | Expected Result |
|----|-------|------|-------|-----------------|
| TC-01 | Successful login with valid credentials | Positive | 1. Navigate to the login page.<br>2. Enter a valid registered username.<br>3. Enter the correct password.<br>4. Click "Log in". | User is authenticated and redirected to the product list page. User's name or account indicator is displayed. |
| TC-02 | Logged-in shopper can view product list and add item to cart | Positive | 1. Log in with valid credentials.<br>2. Verify the product list is displayed.<br>3. Select a product and click "Add to cart".<br>4. Open the cart. | Product list loads with items. Selected item appears in the cart and the shopper can proceed to checkout. |
| TC-03 | Login with valid username but incorrect password | Negative | 1. Navigate to the login page.<br>2. Enter a valid username.<br>3. Enter an incorrect password.<br>4. Click "Log in". | Login fails. A generic error message is shown (e.g., "Invalid username or password"). User stays on the login page and no session is created. |
| TC-04 | Login with non-existent username | Negative | 1. Navigate to the login page.<br>2. Enter a username that is not registered.<br>3. Enter any password.<br>4. Click "Log in". | Login fails with the same generic error message as TC-03, without revealing whether the username exists. |
| TC-05 | Login with empty username and password | Negative | 1. Navigate to the login page.<br>2. Leave both fields empty.<br>3. Click "Log in". | Login is blocked. Validation messages indicate that username and password are required. No request is authenticated. |
| TC-06 | Access product list or checkout directly without logging in | Negative | 1. Open a new browser session (not logged in).<br>2. Navigate directly to the product list or checkout URL. | User is redirected to the login page (or access is denied). Protected content and purchase actions are not available. |
| TC-07 | Account lockout or throttling after repeated failed attempts | Negative | 1. Navigate to the login page.<br>2. Enter a valid username with an incorrect password repeatedly (up to the configured limit, e.g., 5 times).<br>3. Then attempt to log in with the correct password. | After the limit is reached, the account is temporarily locked or throttled, and a message informs the user. Login with the correct password is blocked until the lockout expires or is reset. |
| TC-08 | SQL injection attempt in login fields | Negative | 1. Navigate to the login page.<br>2. Enter `' OR '1'='1` as the username.<br>3. Enter `' OR '1'='1` as the password.<br>4. Click "Log in". | Login fails. Input is sanitized or parameterized, no authentication bypass occurs, no database error details are exposed, and a generic error message is shown. |
| TC-09 | Username with leading/trailing spaces and case variation; password case sensitivity | Edge | 1. Navigate to the login page.<br>2. Enter a valid username with a trailing space (and again with different letter case).<br>3. Enter the correct password.<br>4. Click "Log in".<br>5. Repeat with the correct username and the password in the wrong case. | Behavior follows the defined rules: the username is trimmed or case-handled consistently (per spec), and the password is case-sensitive. Login with the wrong-case password fails with a generic error. |
| TC-10 | Login with maximum-length and special-character credentials | Edge | 1. Navigate to the login page.<br>2. Enter a valid account username/password containing special characters and Unicode (e.g., `user_ñ@#`, password `P@ss w0rd!€`), at the maximum allowed length.<br>3. Click "Log in".<br>4. Then enter values exceeding the maximum length and click "Log in". | Valid max-length credentials with special characters authenticate successfully. Over-length input is rejected or truncated per the spec with a clear validation message, and the application does not crash or error. |
